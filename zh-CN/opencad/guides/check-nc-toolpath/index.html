检查文件格式和方言

读取 G 代码、Heidenhain 对话式程序（.h）与 DIN/ISO（.i）、woodWOP MPR（.mpr）、WangShi PGI（.pgi）和 KDT XML（.xml）并显示路径。G 代码面向 ISO、Fanuc、Haas、Siemens、LinuxCNC、GRBL、Mach3 系列，但并非每台设备的指令和宏都会按相同含义解析。

PGI 和 XML 是 KDT 等板材加工设备使用的程序。与 MPR 一样，会在板上绘制板材尺寸和变量、各个面上的孔、锯槽、型腔和铣削路径。.xml 文件只有在采用 KDT 板材加工格式时才会打开。其他 XML 不会打开，而是给出提示；woodWOP MPRX 则会提示先另存为 MPR 再打开。

仅凭扩展名无法确定原始设备和方言。打开文件后，请将信息面板中的方言、单位和解释警告与原始程序的设置进行比较。查看器判断为 Haas、Siemens 等方言或车床程序时，会在画面上方的提示条中告知；如果判断有误，可以在提示条或信息面板中立即更改并重新读取。

通过示例学习回放和代码行链接

“预览示例”会打开一个在此浏览器中创建的复合 G 代码。您可以查看屏幕操作，而无需选择个人 NC 文件。

  1. 在示例中按“查看全部”或按 F 键，使路径适应屏幕。
  2. 选择代码线或 3D 路径以查看连接的移动。
  3. 在播放栏上更改播放/暂停和速度，并查看工具路径。
  4. 打开“我的文件”，在“信息”面板中查看“单位”、“方言”、“警告”以及“转移”和“快速移动”长度。

当路径大小或形状与预期不符时

首先，确认单位和方言与原始设置一致。检查“查看全部”和工具特定显示状态，并选择相关代码行以精确定位相应的操作。

半径补偿路径、车床模式和旋转轴缠绕均为可选功能。请确认设置符合程序预期，切勿因为所有运动都统一应用了这些设置就认为结果与原始结果完全相同。

如果板材加工文件中缺少某项加工，请在信息面板和加工面板中确认它是已停用的加工，还是不支持的宏或元素。不支持的宏或元素可能只以点显示其位置。在 PGI 和 XML 中，无法读取数值的加工会以“解析失败”留在加工列表中。

区分分析结果和实际设备验证

仅凭刀具路径画面和预估时间无法判断碰撞、控制器动作或加工质量。上机前必须根据原始 CAM、控制器和现场条件另行验证。

报告错误时，请提供方言、单元、问题行和预期移动，并使用您自己创建的最小示例，而不是提交保密的NC（错误报告）。文件由本浏览器处理，不会自动上传到公共问题。
