직접 맡은 역할과 결과

맡은 역할
참고 논문의 그래프 표현과 Q-learning 아이디어를 바탕으로, TSP 환경·모델·학습 루프·삽입 규칙을 연결하는 실험 코드를 구현했습니다.
만들어낸 결과
도시의 위치·거리·방문 상태를 그래프로 입력하고, 모델이 고른 도시를 삽입 휴리스틱으로 경로에 추가하는 탐색 프로그램을 만들었습니다. 공개 코드 재실행에서는 기준선과 비교해 학습이 제대로 작동하지 않는 원인도 추적했습니다.

직접 구현·분석한 것

  • 노드, 엣지, 방문 상태를 담은 그래프 환경과 경로 비용 기록
  • Structure2Vec 임베딩과 Q값 평가
  • 여러 스텝 보상 누적과 경험 샘플링을 잇는 탐색 루프
  • 도시는 모델이 고르고 넣을 자리는 삽입 휴리스틱이 정하는 구조

공개 코드 재실행 · 분석과 검증

단축 학습에서는 무작위 삽입 대비 개선을 확인하지 못했습니다

공개 코드 재실행 · 원래 10,000회 설정 중 100회 학습 · 완전 학습 성능과 구분

원래 설정으로 학습해 보니, 정책이 모든 도시에 같은 Q값을 내며 번호 순서대로 도시를 골랐습니다.

  • TensorFlow 2.15
  • seed 3개
  • 에피소드 10,000 → 100
  • +12%위 50도시 예시 · OR-Tools 해보다 긴 경로
  • 개선 미확인무작위 순서 삽입과 비교한 단축 학습
  • 2가지코드에서 찾은 원인
  1. 기대

    학습한 Q값이 경로를 짧게 만드는 도시를 고른다

  2. 실제

    모든 도시의 Q값이 같아져 번호 순서대로 골랐다

  3. 원인

    정규화 없는 이웃 합으로 값이 폭증했고, TD 목표가 시작 도시만 봤다

문제와 해결

  1. 문제도시 수와 방문 상태가 달라져도 같은 모델로 다음 후보를 평가해야 합니다.

    해결도시와 거리를 그래프로 표현하고 Structure2Vec으로 관계를 임베딩해, 방문하지 않은 도시의 Q값을 평가하도록 구성했습니다.

  2. 문제다음 도시를 고르는 것만으로는 경로의 어느 위치에 넣을지 정해지지 않습니다.

    해결도시 선택은 학습 모델이, 삽입 위치는 경로 길이가 가장 덜 늘어나는 자리를 찾는 휴리스틱이 맡도록 결합했습니다.

  3. 문제짧은 경로가 나와도 학습 효과인지 삽입 규칙의 효과인지 구분하기 어렵습니다.

    분석·검증무작위 도시 순서에도 같은 삽입 규칙을 적용해 비교하고 Q값과 TD 목표 계산을 추적했습니다. 단축 학습에서는 학습 정책의 개선을 확인하지 못했습니다.

관찰한 원인과 남은 과제

  1. Q값 폭증

    정규화 없이 완전 그래프 전체를 더해 Q값이 수백만 단위로 커졌고, 갱신 손실이 10¹⁵ 단위까지 튀었습니다.

  2. TD 목표값 오류

    목표값이 남은 도시가 아니라 늘 시작 도시의 Q값으로 계산됐고, n-step 다음 상태도 한 칸 어긋나 있었습니다.

  3. 에피소드 100회로 줄임

    큰 그래프는 에피소드당 약 45초라 10,000회면 seed당 5일이 넘습니다. 횟수만 줄이고 나머지 설정은 그대로 뒀습니다.

결과를 읽는 기준

  • 원논문 그대로의 재현 아님 (target network 없음, n-step 방식 다름)
  • 설정된 에피소드의 1%만 학습
  • 끝까지 학습했을 때의 성능은 알 수 없음
