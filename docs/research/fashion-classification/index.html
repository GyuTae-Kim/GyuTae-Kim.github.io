예측 쏠림의 원인을 증강 설정과 숏컷 오류에서 찾았습니다

공개 데이터 Fashion-MNIST로 같은 코드를 돌려도 예측이 한쪽으로 쏠렸습니다. 원인은 증강 설정과 숏컷 연결 오류였습니다.

  • RTX A6000
  • TensorFlow 2.15
  • Fashion-MNIST 4클래스(드레스, 코트, 바지, 티셔츠)
  • 10 epoch
  • 48.9% → 94.4%증강만 끈 비교 · Fashion-MNIST · seed 0
  • +29.8%p숏컷 연결만 수정 · 같은 seed 0
  • 0%원래 설정의 코트 재현율 · 같은 seed 0

문제와 해결

  1. 문제의류 종류별 사진 수가 달라 학습 표본이 일부 클래스에 치우칩니다.

    해결학습·검증 데이터에서 각각 가장 적은 클래스의 표본 수에 맞춰 다운샘플링했습니다.

  2. 문제전체 점수만으로는 어떤 옷을 서로 혼동하는지 알기 어렵습니다.

    해결클래스별 정밀도·재현율과 혼동행렬을 기록하고, 드레스·아우터 등 혼동 사례를 사진과 함께 분석했습니다.

  3. 문제예측이 한쪽으로 쏠리는 현상에 데이터와 코드 설정이 함께 영향을 줄 수 있습니다.

    원인 분석Fashion-MNIST에서 증강·숏컷·정규화 설정을 하나씩 바꿔 비교해, 쏠림의 원인을 코드 설정에서 찾았습니다.

관찰한 원인과 남은 과제

  1. 증강이 의도보다 셌음

    약한 증강을 의도했지만 실제로는 ±72° 회전, 상하 뒤집기, 절반 크기 축소로 동작했고, 캐시 때문에 첫 epoch의 변형이 끝까지 고정됐습니다.

  2. 숏컷 연결 오류

    identity 숏컷이 원래 입력 대신 BN과 ReLU를 거친 값을 넘겼습니다. ImageNet 가중치는 오류 없이 들어가 겉으로는 드러나지 않았습니다.

  3. 평가 방식

    README의 recall은 0.5 임계값 기준이었고 평가에 검증 데이터를 다시 썼습니다. 여기 올린 정확도는 겹치지 않는 테스트 세트로 잰 값입니다.

결과를 읽는 기준

  • README의 평가는 검증 데이터를 다시 써서 독립 테스트가 아님
  • 오류 원인(불균형, 촬영 구도)까지는 검증하지 않음
  • 아래 수치는 Fashion-MNIST 4클래스로 10 epoch 학습한 결과
최근 프로젝트와 이어지는 점

클래스별 오류를 나눠 보고 평가 분할이 무엇을 뜻하는지 따져 본 경험이, 지금 CAD 가공 특징의 라벨과 모델을 평가하는 방식에도 남아 있습니다.
