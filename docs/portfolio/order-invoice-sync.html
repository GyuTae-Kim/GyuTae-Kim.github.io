송장 연동에서 반복되던 전송 오류 개선

6주 동안 전체 전송 때마다 반복되던 실패를 없앴습니다

배송이 시작된 주문의 운송장 번호를 연동 서비스를 거쳐 외부 쇼핑몰에 등록합니다. 한 번 등록된 번호는 연동으로 바꿀 수 없어, 잘못 처리되면 담당자가 쇼핑몰 관리자에서 직접 고쳐야 합니다. 이 연동을 서비스 감시에 연결하고, 실패 알림을 따라가 같은 송장이 두 번 전송되거나 이미 등록된 주문이 계속 실패하던 원인을 찾아 고쳤습니다.

  • 6주전체 전송 때마다 반복되던 같은 실패 해결
  • 2회 → 1회표기만 바뀐 송장의 전송 횟수
  • 2회 → 0회같은 엑셀을 다시 올릴 때 대표 운송장 변경
맡은 역할
송장 연동의 실패 기록을 서비스 감시에 연결하고, 알림으로 드러난 전송 오류의 원인을 찾아 전송과 엑셀 업로드 처리를 고쳤습니다. 연동 기능과 송장 등록 화면은 팀원이 만들었고, 화면에서는 전체 전송 건수와 안내만 맞췄습니다.
  1. 1감시 연결연동 실패와 끝나지 않은 실행을 기록해 알림으로 받음
  2. 2중복 전송동시 전송 충돌과 하이픈 표기 차이로 생긴 재전송 제거
  3. 3엑셀 재업로드바뀐 것이 없으면 운송장을 다시 쓰지 않음
  4. 4이미 등록된 송장등록 번호와 비교해 완료로 기록하거나 고칠 곳을 안내
자세히 · 문제와 해결, 화면

  1. 문제일괄로 배송을 시작하면 같은 순간 시작한 두 전송이 임시 파일 하나를 함께 썼습니다. 둘 다 실패로 기록됐고, 그중 하나는 실제로 등록됐는데도 미전송으로 남았습니다.

    해결파일 이름을 요청마다 고유하게 짓고, 실패해도 임시 파일을 지웁니다. 연동 서비스가 돌려준 거절 사유도 함께 기록합니다.

  2. 문제하이픈만 다른 같은 운송장 번호를 바뀐 것으로 보고 다시 보냈습니다. 두 번째 전송은 실패했고, 완료 표시가 지워진 주문은 미전송 목록에 남았습니다.

    해결택배사가 다르거나 숫자가 다를 때만 변경으로 봅니다.

  3. 문제하루치가 쌓이는 택배사 엑셀을 올릴 때마다 대표 운송장이 옛 번호로 갔다가 돌아왔고, 배송 중인 주문은 그때마다 다시 전송돼 실패가 두 번씩 기록됐습니다.

    해결주문마다 마지막 번호만 한 번에 반영하고, 바뀐 것이 없으면 쓰지 않습니다.

  4. 문제번호가 바뀌었다 돌아온 주문 하나가 완료 표시를 잃어, 9월 초부터 6주 동안 전체 전송 때마다 같은 실패가 났습니다.

    해결이미 등록됐다는 응답이 오면 마지막 등록 번호와 비교합니다. 같으면 완료로 기록하고, 다르면 등록된 번호와 함께 쇼핑몰 관리자에서 고치라고 안내합니다.
