제조 소프트웨어 개발 노트 · 김규태 Sean Kim

가구 설계를 제조 데이터로 연결하는 소프트웨어 개발

가구 모델을 화면에 그리는 일과 실제 제조에 필요한 데이터를 만드는 일은 연결되어 있습니다. 패널 인식 연구와 Wedraw Pro 개발 사례를 바탕으로 설계 변경이 제조 단계까지 이어질 때 고려한 문제를 정리합니다.

이 글에서 확인할 내용
  1. 패널의 형상과 역할을 나누어 봅니다
  2. 파라메트릭 설계는 변경 규칙을 전달하는 일입니다
  3. 판재 회전과 실제 투입 방향을 출력 규칙에 담습니다
  4. 운영에서는 서버 상태와 업무 완료를 함께 확인합니다

패널의 형상과 역할을 나누어 봅니다

가구 패널 인식 연구에서는 패널과 접합면을 분석하고 AI로 패널 역할을 인식해 크기 변경 규칙을 계산했습니다. 비슷한 직육면체여도 어느 방향으로 놓이고 다른 패널과 어떻게 맞닿는지에 따라 역할과 변경 규칙이 달라질 수 있습니다.

해당 연구는 팀 프로젝트입니다. 직접 맡은 범위는 패널·접합면 분석, AI 연구와 계수식 계산이며, 전체 제품을 혼자 개발했다는 의미는 아닙니다.

파라메트릭 설계는 변경 규칙을 전달하는 일입니다

너비나 높이를 바꾸면 어떤 패널을 늘리고 어떤 위치를 옮길지 계산해야 합니다. 형상에서 역할을 찾는 단계와 치수 변경에 따른 규칙을 계산하는 단계를 나누면, 잘못된 결과가 인식 문제인지 규칙 문제인지 살펴볼 수 있습니다.

이 과정에서 중요한 것은 그럴듯한 화면 한 장보다 입력 형상, 접합 관계, 계산된 규칙과 변경 결과를 연결해 설명할 수 있는가입니다. 상세 연구 화면과 확인한 범위는 패널 인식 사례에 정리했습니다.

판재 회전과 실제 투입 방향을 출력 규칙에 담습니다

Wedraw Pro에서는 SketchUp 가구 설계에서 도면·발주·제조 데이터와 생산 투입으로 이어지는 흐름을 개발했습니다. 직접 리딩한 범위는 제조 데이터 출력과 생산 투입이며, 도면·발주 초기 개발도 리딩했습니다.

판재를 회전하거나 뒤집으면 가공 위치뿐 아니라 엣지밴드와 결 방향도 함께 따라가야 합니다. 네스팅기 기준과 스키퍼 기준의 가공 파일을 나누고, 라벨에 뒤집기 표시와 투입 화살표를 넣어 작업자가 어느 방향으로 넣을지 알 수 있게 했습니다.

도어컵을 뒷면에 가공해야 하는데 공구가 위쪽에 있는 경우에는 도어의 좌우와 가공 면을 함께 뒤집는 규칙이 필요했습니다. 화면의 좌표 변환과 현장의 투입 방향을 따로 설명하면 놓치기 쉬운 문제입니다.

  • BOM·라벨·가공 도면·MPR·PGI를 같은 설계에서 출력합니다.
  • 공개 사례의 실제 설계 데이터인 가구 5개·판재 66장에 대해 출력과 별도 계산한 회전 결과를 비교했습니다.
  • 출력 파일과 뒤집기 표시로 가공 위치를 되살리고 설계와 대조했습니다.
  • 이 검증에 현장 기계 설정·작업자 투입·실제 CNC 가공은 포함하지 않았습니다.

운영에서는 서버 상태와 업무 완료를 함께 확인합니다

설계·제조와 연결되는 서비스에서는 서버가 응답하더라도 송장 전송처럼 실제 업무가 실패할 수 있습니다. 운영 감시 사례에서는 서버 상태에 더해 업무 결과, API 오류와 사용자 PC 프로그램의 오류를 모아 원인을 확인했습니다.

여기서 정리한 연구·제품 개발·서비스 운영은 서로 다른 사례입니다. 각 사례의 역할과 증거를 연결해 두었으며, 화면이나 자동 검사 통과를 현장 제조 품질의 최종 승인으로 표현하지 않았습니다.
