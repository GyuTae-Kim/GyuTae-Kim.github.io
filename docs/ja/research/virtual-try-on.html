2021年・学部研究生
公開コード

Androidアプリでポートレート写真と着用服を選択すると、サーバーは仮想着用画像を返すフローを作成しました。

  1. 1人物写真・着せる服の選択

    Androidアプリでポートレート写真と衣類IDを転送する

  2. 2人体パージング、ポーズ、衣服マスク

    ACGPN入力形式で整理

  3. 3着用イメージの生成

    Flaskサーバーがアプリに戻る

ACGPNと人体解析、ポーズ推定公開モデルを結んだ統合実装

担当した役割と成果

担当する役割
公開されているバーチャル試着モデルに必要な入力前処理と衣類マスクを構築し、FlaskアップロードAPIとKotlin・Retrofit Androidクライアントを接続しました。
成果
人物写真と選択した衣類を受け取り、前処理、試着画像の生成、そしてアプリへの結果の返却までの一連の統合フローを構築しました。生成モデル、ポーズ推定モデル、人体パースモデルは既存のものを再利用し、入力構成、マスク処理、サーバーとアプリ間の連携部分は独自に実装しました。

公開コードの再実行：分析と検証

アップロードから試着結果の返却までを確認し、マスクエラーを分析しました

公開コードの再実行（VITON-HDテスト画像、CC BY-NC 4.0）。顔にはモザイクを適用。以下の所要時間はCPUでの実験値です。

サーバーのアップロードAPIを再実行して試着画像を取得したところ、40着の服のうち13着で、GrabCutの矩形範囲が画像の外にはみ出し、マスク（切り抜き範囲）が背景にまで広がってしまう事象が発生しました。

  • Apple M1 Pro CPU
  • PyTorch
  • 公開モデルの重み
  • サーバーアップロードAPIを再実行
  • 13 / 40着マスクが背景にはみ出している服
  • 0.93 → 0.96矩形修正後のマスクIoU
  • 4.9秒1リクエストあたりのCPU中央値

問題と解決策

  1. 問題バーチャル試着モデルでは、人物写真に加え、ポーズ、身体部位、衣類領域の情報を所定の形式で入力する必要があります。

    解決公開されている人体パース（セグメンテーション）およびポーズ推定モデルの出力をACGPNの入力形式に合わせ、GrabCutを用いて衣類のマスクを作成する前処理を組み込みました。

  2. 問題複数のモデルのファイル入出力は、ユーザーが直接扱うには手順が複雑です。

    解決Flask Upload APIは前処理と推論を実行し、結果の画像を返すように設定し、AndroidクライアントをRetrofitにリンクしました。

  3. 問題衣類のマスクに背景が混ざると、生成された服と胴体が一緒にぼやけてしまう可能性があります。

    補完実験公開コードの再実行において、GrabCutの初期矩形（バウンディングボックス）が画像境界を越えてしまう問題を確認しました。そこで、矩形を画像内に収まるよう制限し、その際のマスクのIoU（Intersection over Union）の変化を比較実験によって検証しました。

観察された原因と残された課題

  1. GrabCut正方形エラー

    矩形 (1, 1, w, h) が画像の境界を越えており、背景の手がかりが上と左の1列分しかなかったため、40件中13件でマスクが背景にまで広がってしまいました。

  2. 3種類の失敗パターン

    マスクが背景にはみ出すと胴体がぼやけ、袖の長さを変えると腕に残像が生じ、丈が異なると元の服の模様が裾の下に残ってしまいます。

  3. SSIMの読み方

    同じ衣服を再度着せて、オリジナルと比較した値です。衣服の外側部分は入力がそのまま使用されるためスコアが高く、ACGPN論文の値とは比較できません。

  4. データと重み

    VITONデータは配布が妨げられ、VITON-HDテストイメージを書き、ACGPNとOpenPoseの重みは非商業研究用に公開されたものです。

結果の読み方

  • 画質や速度の改善ではなく、統合的な実装
  • 公開されている重みを使用して、数十枚のテスト画像を実行した結果
  • 製品レベルのパフォーマンスや商用運用が可能かどうかは示されません
